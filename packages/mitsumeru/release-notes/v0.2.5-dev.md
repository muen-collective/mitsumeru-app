Internal build — carries the `-dev` suffix; the update channel it belongs to is
`dev`.

**The same app, on a new harness.** This build re-pins DeepSeek Harness
0.1.7-rc.1 → **0.2.0-rc.2**. Nothing in the shell changed: the update banner,
Muen sign-in, the avatar menu and the language switcher are exactly what
0.2.4-dev shipped. That is deliberate — this release exists to exercise the
update path end to end: a 0.2.4-dev machine is offered this build by the app
itself, downloads it through the banner, and restarts into the new harness.

**What the harness brings.** The 0.2.0 line adds two composed client features
this build keeps on — **keyboard shortcuts** (`shortcuts` + `ui-shortcuts`
rows) and a **session-log page in Settings** (`ui-settings-session-log`) — and
splits the DeepSeek account plumbing (`dsh-llm-deepseek-account` /
`-api-key`). The old hard-disabled `ui-schedule` row is gone from the shipped
composition; scheduling now lives in an upstream *experimental* bundle that
upstream's own shipped profiles leave switched off — as does this build.

**Upstream added product analytics and OTLP telemetry — both stay off here.**
0.2.0-rc.2 composes a `product-analytics` client row and a
`desktop-product-telemetry` OTLP exporter, **both gated on the profile being
named `desktop`**. Our profile is `mitsu`, so the gates never pass and neither
row loads — the same mechanism, and the same deliberate outcome, as the
sidebar browser tab. Stated here so "upstream added telemetry" is never a
surprise later.

**The bump's own findings, fixed in this commit.** The supply-chain age gate
holds the harness closure as an explicit, version-reviewed exception list, so
a re-pin must retarget that list (297 entries, now at 0.2.0-rc.2; the gate
itself is untouched and passes). And `smoke-native` hard-coded sharp's binary
filenames (0.35.4 / libvips 8.18.6), which upstream bumped under it — the
check now resolves the real filenames, so a future bump cannot fail it on a
stale fixture.

Every bump is audited against the three upstream breakage classes; all came
back clean here: the settings/service surface (the brand renders from a live
window, and all seven shipped plugins mount with zero console errors),
composition gates (row by row, above), and profile bundles (a fresh profile's
first boot logs no `skipping profile bundle`).

**Unchanged from 0.2.4-dev.** Muen sign-in still has no production service
behind it, and private-plugin gating is not here. Windows ships in this cut as
before — unsigned, so first run needs one *More info → Run anyway* click.

Wraps DeepSeek Harness 0.2.0-rc.2 (from 0.1.7-rc.1).

Packaged for all three targets — `Mitsumeru-0.2.5-dev-arm64.dmg` +
`-arm64-mac.zip` (Apple Silicon), `Mitsumeru-0.2.5-dev.dmg` + `-mac.zip`
(Intel) and `Mitsumeru Setup 0.2.5-dev.exe` (Windows x64). Both Mac builds are
notarized and stapled; the feed is the merged `dev-mac.yml`, with `dev.yml`
for Windows.

Gates: `check:label` / `check:identity` / typecheck; `pnpm smoke` (5/5);
`pnpm smoke:native` (native binaries signed and working); `pnpm verify:surfaces`
(the brand seat renders from a live window); `pnpm verify:mount` (seven plugins,
zero console errors); `pnpm verify:release` (36/36, both Mac targets);
`pnpm verify:artifacts` (16/16 — every archive, including the NSIS payload);
`pnpm verify:docs` (the docs agree with this shell). `pnpm smoke:updater` is the
one gate not re-run here: a running installed app holds the single-instance
lock it needs; it passed 14/14 on 0.2.4-dev and the updater code is unchanged.

Install: `Mitsumeru-0.2.5-dev-arm64.dmg` (Apple Silicon),
`Mitsumeru-0.2.5-dev.dmg` (Intel), or `Mitsumeru Setup 0.2.5-dev.exe`
(Windows x64), from this release's assets. A 0.2.4-dev machine is offered this
build by the app itself — the first real update through the banner.
