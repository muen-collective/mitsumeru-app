# Mitsumeru 0.2.8-dev

Internal build — carries the `-dev` suffix; the update channel is `dev`.

Wraps DeepSeek Harness **0.2.1-rc.2**, unchanged. This cut is the updater's: one loop fixed, and
the regression test that would have caught it.

## What changed

- **A scheduled check can no longer move you backwards** (founder, 2026-10-23: *"i updated and
  restart but i did again so I think theres a bug somewhere"*). A build carrying an **unpublished**
  version sat ahead of the channel, so every check found the older published version, and because
  `allowDowngrade` was `true` for every check, electron-updater offered it, `autoDownload` fetched
  it, and the banner offered a restart that could only ever go back. The version string never moved
  forward, so the next check offered it again — a loop with no exit, driven by a timer.

  `allowDowngrade` now follows the **trigger**: a person asking (the pill, the menu's *Check for
  Updates*) may roll back; a scheduled check, a resume check and the startup check may not. Rollback
  is a decision, not a side effect.

- **A downloaded version equal to the running one is never offered.** electron-updater already
  filters equal versions itself, so this is the last word rather than the first defence — but it
  costs one comparison and closes the case where a cached download and the running bundle disagree.

- **The updater smoke gained case C**: a stand-in feed serving a genuinely older version, asserting
  that a scheduled check neither offers it nor downloads it. Mutation-tested — restoring
  `allowDowngrade = true` fails the case with *"a scheduled check OFFERED the older 0.2.8-alpha.1"*,
  which is exactly the loop that was reported.

## A note on the fixture, because it bit

The first version of case C used `0.2.8-older` as the "older" version. Pre-release tags sort
**alphabetically** in semver, so `older` > `dev` and the app correctly offered it as an update —
the test was wrong, not the fix. It now uses `-alpha.1`.
