Internal build — carries the `-dev` suffix; the update channel it belongs to is
`dev`.

**The app now announces its own updates.** Until now a release reached you
because a person said so — the shell checked, downloaded and waited, but said
nothing, and an update could sit unseen until someone mentioned it. A 36 px
shell-owned strip at the top of the window surfaces that state: a check you
trigger flashes "up to date" for three seconds, an available update offers
Download, progress runs against a named version, and a finished download offers
Restart to update. A failure shows when you asked for a check, or when an update
already in flight died, and stays quiet otherwise (10 s); dismiss hides the
strip until the state next changes. It has to be shell-owned — `quitAndInstall()`
is an Electron API, and a harness plugin cannot drive any of this.

Running the five states against the packaged app with a local stand-in feed
caught two bugs, both fixed here: an error after a failed restart hid itself
(the strip still believed the state was `downloaded`), and the progress line
read "Downloading v… 22%" because download-progress events carry no version of
their own.

**Muen sign-in, in the slot DeepSeek Desktop uses.** The lower-left avatar is
that same seat: signed out it shows the Muen mark, and a click starts sign-in —
GitHub OAuth in the browser, a `mitsumeru://auth/callback?code=…` deep link back
into the app, and a code exchange the shell performs in the main process. The
session lands encrypted (`safeStorage`) at `<userData>/auth/session.enc`; the
token never leaves the main process, and the injected overlay only ever sees the
profile. Signed in, the avatar shows your picture (your initial if the image
fails to load), with a **PRO** badge when the session says `membership: pro`.
The deep link needed a `protocols` entry in the build config — without it macOS
hands the URL to nobody and sign-in can never complete.

**The avatar opens a menu, and the language switcher moved into it.** The row
opens on click, the DeepSeek Desktop pattern: Language (English / 中文),
separator, Sign out. The language item writes the harness's own locale
preference over the same wire Settings → General uses, so the two surfaces
cannot disagree — and the client applies it live, `html lang` flipping in about
2.5 s with no reload. The overlay takes the new language on the click itself, so
its own bilingual labels do not trail the app; the menu closes on an outside
click and on Esc, and a failed switch shows an inline error instead of ignoring
the click.

**What is deliberately not in this build.** Sign-in was verified against a local
mock auth server; the production service is not standing yet, and the build
points at `mitsumeru.vercel.app` (`MITSUMERU_AUTH_ORIGIN` moves it for a run).
Private-plugin gating — the part that reads membership and unlocks the Muen set
— is not here either.

Wraps DeepSeek Harness 0.1.7-rc.1 — unchanged. The re-pin to 0.2.0-rc.2 follows
as its own release, so a shell change and a harness change can be told apart if
something misbehaves.

Packaged for both Mac targets — `Mitsumeru-0.2.4-dev-arm64.dmg` +
`-arm64-mac.zip` (Apple Silicon) and `Mitsumeru-0.2.4-dev.dmg` + `-mac.zip`
(Intel) — signed with a Developer ID, notarized and stapled (every artifact
carries its ticket), with the merged `dev-mac.yml` feed. The Windows installer
follows with the production cut. Gates: `check:label` / `check:identity` /
typecheck; `pnpm smoke` (5/5);
`pnpm smoke:updater` (14/14, against the packaged build); the five banner
states, sign-in and sign-out, session restore across a SIGKILL and relaunch,
and the language switch — all against the packaged app, all screenshot-asserted
(`artifacts/current-*`, `error-*`, `downloaded-*`, `auth-*`, `menu-*`).

Install: `Mitsumeru-0.2.4-dev-arm64.dmg` (Apple Silicon) or
`Mitsumeru-0.2.4-dev.dmg` (Intel), from this release's assets. A machine on the
dev channel is offered it by the app itself. From this build on the app
announces its own updates — this is the last release that had to be relayed by
hand.
