# Mitsumeru 0.2.7-dev

Internal build — carries the `-dev` suffix; the update channel is `dev`.

Wraps DeepSeek Harness **0.2.1-rc.2**, unchanged from 0.2.6-dev. This cut is the shell catching up:
one behaviour fix, no harness change.

## What changed

- **A new workspace folder can be named** (founder, 2026-10-22: *"I can open finder but when I try
  to create new folder, it can't give it a name"*). The sidebar's new-project flow opened the
  harness's own macOS picker, which is an `NSOpenPanel` run by a **separate `osascript`
  accessory process**. That panel is never the app window's key window, so *New Folder* created a
  folder but its rename field refused every keystroke — the name had to be accepted as
  `untitled folder` and renamed afterwards in Finder.

  The shell now exposes `__DSH_DIRECTORY_PICKER__` — the same global DSH's own desktop exposes —
  and answers it with an Electron sheet attached to the main window (`openDirectory` +
  `createDirectory`). Naming a folder is ordinary text entry again: type, press Return, choose.
  The harness client prefers that bridge whenever it exists, so nothing in the pinned harness
  changed and no upstream patch is carried.

  Verified on a live run before the cut: the dialog's owner is the app, no `osascript` process is
  involved, the sheet carries *New Folder / Cancel / Choose*, and a pick completed with a newly
  created folder. The founder then drove the same dialog by hand and confirmed the name can be
  typed.
