Internal build — carries the `-dev` suffix; the update channel it belongs to is
`dev`.

**The composer is back, and the reason it left is fixed at the root.** 0.1.8-dev
shipped without the message input bar. The harness was not the problem; the tree
we packaged was. `prepare-harness.sh` staged the pinned DSH release but let every
`@deepseek-ai/*` package underneath it resolve on its own, so the closure could —
and did — land one version off the release that declares it, and the composer is
what disappeared when it did. The staged install is now pinned end to end: the
script reads the pinned release's own manifest out of the pnpm store, takes the
exact version the store resolved for every `@deepseek-ai/*` package that release
declares, and writes those pins into `pnpm-workspace.yaml` before staging. The
pins and the closure check are derived from the same source, so they agree by
construction instead of by attention. No network call, and a re-pin is now the
only thing that moves a transitive version.

**A new harness underneath: DeepSeek Harness 0.1.6-alpha.2**, up from
0.1.5-rc.1. This is where the composer came back and where the upstream features
since 0.1.5-rc.1 arrive.

**The white-label plugin now ships inside the app.** `@muen/dsh-white-label` was
a plugin you installed; it is now part of the build. It is vendored by
`prepare-harness.sh`, symlinked into the profile on every launch, and named in
`SHIPPED_PLUGINS` — and the shipped set is recomputed on every launch rather than
written once on first run, which is what lets a new bundled plugin reach a
machine that already has a profile. That last part is the 0.1.4-dev failure
written down: a shipped plugin could never reach an installed app, and the only
way in was to delete the profile and the person's sessions with it. What you own
survives the recompute — your own bundles keep their order, your added plugins
are not dropped.

What it does, for anyone who has not used it: brand files live in
`<DSH_HOME>/brand/` (`icon.*` for the mark, `logo.*` for the sidebar lockup), and
Settings → Brand configures the two mark seats independently — the 24 px sidebar
rail and the 34 px hero mark — each with its own switch. An SVG wins over a raster
inside a seat because it is rendered inline and can follow the theme; a raster is
drawn exactly as exported, so a dark-on-transparent mark disappears in dark mode.
Uploads are validated on the way in and refused with the expected filename in the
message. Two bugs are fixed in this release: the brand upload section had an ID
conflict, and the sidebar could come up without the brand at all.

**Intel Macs and Windows, from the same commit.** The build now targets macOS
`arm64` and `x64`, and Windows `x64` as an NSIS installer. Previous releases were
arm64 only, so this is the first build that can go on the Intel Mac and the
Windows rigs.

**Electron 44.0.0, pinned.** Deliberately not 44.4.1: the newer line breaks
`node-addon-require-builtin`, which the harness's native addon path needs.

**Two gates that did not exist last release, and one uninstaller.**
`verify:survives-update` throws away `DSH_HOME`, installs the plugin, writes a
brand icon, boots the app, then *replaces the harness tree* to simulate an update
and boots again — it proves the brand survives the replacement, which is the
whole claim the bundled plugin makes. Building it found the bug it was written
for: two separate `inject()` calls on the same slot means the second never fires;
one generator yielding both rows is the fix. `verify:distribution` starts one
step earlier than every other gate, at "the file a stranger actually downloads":
it fetches the marketing site, reads both of the page's download sources, and
checks that the API calls target the repo we publish from, that no link points at
a retired repo (matched structurally, so the next rename is caught too), that the
modal's asset regex still matches our real dmg name, that the hero fallback and
the live resolution agree, and that the artifact itself returns 200, matches
`dev-mac.yml`'s sha512, is accepted by Gatekeeper, is stapled, and reports the
version we think we shipped. It was verified both ways — a gate that has never
failed proves nothing — 12/12 against the fixed site and 8 failures against the
pre-fix bytes. The uninstaller is for Noi, who has both apps installed: the
retired "Mitsumeru Dev" app stores its data under `dsh-desktop-dev`, which
matches nothing visible in Finder, so the script matches both installs by bundle
id and never by name, and verifies the new app before and after. It needs no
admin password, and its README says to right-click → Open, because a downloaded
`.command` is quarantined and macOS refuses it on a double-click.

Wraps DeepSeek Harness 0.1.6-alpha.2, pinned, including the DeepSeek 4.1 model
adapter.

**Signing: signed, not notarized.** The app carries a Developer ID signature
(THUY QUANG PHAM, `4Q6GC57QG4`, hardened runtime, secure timestamp). No
notarization ticket is stapled to `Mitsumeru.app` or to the dmg — `xcrun stapler
validate` reports "does not have a ticket stapled to it" for both, and `spctl -a
-t open --context context:primary-signature` on the dmg reports `rejected` /
`source=no usable signature`. 0.1.7-dev and 0.1.8-dev were notarized and stapled;
this build was not — `pnpm notarize` was not run. Anyone outside the team gets
the Gatekeeper refusal and needs right-click → Open.

Gates: `pnpm verify:release`, `pnpm verify:surfaces`, `pnpm verify:mount`,
`pnpm verify:survives-update`, `pnpm verify:distribution`.

Install: download `Mitsumeru-0.1.9-dev-arm64.dmg` (or `-0.1.9-dev.dmg` for Intel
Macs, `Mitsumeru.Setup.0.1.9-dev.exe` for Windows).

## Release hygiene — read before this is announced

Four things do not line up, and three of them are on the published release rather
than in the build.

1. **The release body says Electron 44.4.1; the shipped app is 44.0.0.** Read from
   the installed bundle's `Electron Framework` `CFBundleVersion`. The pin to
   44.0.0 landed in `c0f175a`, after the body was written.
2. **The tag does not identify what shipped.** `v0.1.9-dev` points at `ae03ab2`
   ("bump version to 0.1.9-dev"), but the artifacts were built from `c0f175a`,
   one commit later — the commit that pins Electron and adds the x64/Windows
   targets. Rebuilding from the tag produces different binaries than the
   published dmg and exe.
3. **`v0.1.9-dev` is published with `prerelease: false`.** Every other `-dev`
   build is `true`, and `app-update.yml` declares `releaseType: prerelease`.
   Confirm the dev channel still resolves this release before telling anyone the
   app will offer it by itself.
4. **The copy installed on this machine has diverged from the release, and the
   divergence broke its seal.** Three files inside `/Applications/Mitsumeru.app`
   were edited at 20:37–20:58 on 2026-09-17 — `@muen/dsh-white-label/lib/index.js`,
   `@muen/dsh-white-label/lib/client.js`, and
   `@deepseek-ai/dsh-client-ui-conversation/lib/client.js` plus the
   `client.js.muen-unpatched` backup the hero-tagline patch writes.
   `codesign --verify` now fails with "a sealed resource is missing or invalid"
   and names exactly those files. The hero-tagline work behind those edits
   (`brandTagline`, the `conversation.hero.tagline` occupant) is **not in this
   release** — it is uncommitted in `muen-plugins` on top of `b493fdf`, and the
   tarball it was built from is `/tmp/muen-dsh-white-label-0.1.0-dev.tgz`. Any
   patch applied inside the app bundle costs the signature; that is how the
   tagline seam is currently delivered, and it is worth deciding deliberately.
