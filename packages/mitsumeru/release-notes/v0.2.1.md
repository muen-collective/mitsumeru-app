Production build — the `-dev` suffix stays off and this leaves the `latest`
channel, like 0.2.0. Version 0.2.1 adds the quality-of-life plugin set.

**This release is arm64-only, deliberately, for the same measured reason as 0.2.0.**
`prepare-harness.sh` stages one host closure for every target, so the x64 and Windows
builds receive Apple Silicon native addons and an Intel process cannot load them. The
manifest lists only arm64 artifacts, so an Intel client finds no suitable file and stays
where it is rather than being handed a build that will not start. Intel and Windows
remain on 0.1.9-dev until the staging learns platform handling.

## What's new: the daily-driver set

Four plugins built to make Mitsumeru livable as the every-day app — the surfaces that
were being missed after moving off Kun — now ship inside the build:

- **Turn summary** — one muted, localized row per finished turn: *Processed 1m 26s ·
  12 steps · Edited 3 files*. It expands into what the turn actually did.
- **Changes card** — a changed-files card at the end of a turn: *Edited 3 files +6 −1*
  with per-file rows, computed from the turn's own file tools, so it also appears where
  the Host's change recorder announced nothing.
- **Codex fold** — finished turns fold, and the thinking/tool/context runs between prose
  collapse into one summary chip per run; expanding shows the native rows again.
- **Context reminder** — a full-width banner above the composer once a session passes a
  model-aware threshold (`max(floor, min(percent% × window, ceiling))`, default 35% capped
  at 300K and floored at 25K), offering a fresh session, a token-banded snooze, or
  dismissal — plus **Settings → General → Context reminder**, the row that owns the policy.

The first three are Client-only surfaces over the conversation; the fourth adds one
preference row and reads the same `contextPressure` projection the harness's own context
meter reads. Each has an empty Host half, so nothing about them can drift from the
harness's own state.

## The set is composed into the app, not offered by it

`SHIPPED_PLUGINS` in the shell is one literal list, and `ensureProfile` recomputes the
profile's bundle list from it on **every launch**. So an app that is already installed
gains these four on the next start, without deleting the profile and without touching
sessions, settings or the brand. They are vendored into the harness resource by
`prepare-harness.sh` — that is, they sit inside the code signature, rather than being
added to an installed app afterwards.

## What deliberately does not ship

**`dsh-auto-collapse` (community).** Codex fold is its localized fork, and the two fold
the same runs: shipping both double-folds a single conversation. The dev profile had the
community package installed (already uncomposed) and it has been removed. Everything else
community stays where it belongs — in the market, installed per profile:

- **browser-skill** needs its Chrome extension, so it cannot work as a baked-in surface.
- **codex-connect** is a third-party OAuth provider that updates itself from the registry;
  vendoring it would freeze an alpha inside a signed artifact and make its updates ours.

The rule this makes explicit: the app ships Muen's own plugins; the market serves the
community's.

## One visual defect fixed on the way in

A folded-work summary chip was rendering **one size larger than every native row around
it** — 14px where the harness's rows are 13px — and it did so invisibly: the chip's
stylesheet declared the right tier, but the chip sets `font: inherit` inline on a button
inside the conversation body, and the inline declaration wins.

The chip now follows the harness's published row contract (`DisclosureRow.module.css`:
title on the secondary tier, row height / leading box / glyph edge shifted by
`--dsh-content-font-delta`), so it also tracks the Settings font-size preference the way
native rows do. The distinction between our rows and the harness's moves to colour, where
it belongs: our labels stay one step dimmer, and the chip's detail — previously *brighter*
than its own label — takes the caption tier.

## Where the source lives

The four are published from
[`muen-collective/muen-plugins`](https://github.com/muen-collective/muen-plugins)
(`plugins/dsh-turn-summary`, `dsh-changes-card`, `dsh-codex-fold`,
`dsh-context-watchdog`), and vendored into this app as byte-identical mirrors. They were
developed as workspace links with no version history; this release is their promotion.

## Known, not fixed in this release

- `verify:survives-update` fails: `@muen/dsh-white-label` imports
  `@deepseek-ai/schemastery` without declaring it, so installing that plugin **from
  source** cannot resolve it. The shipped app is unaffected — the vendored copy resolves
  it beside the harness tree. Carried from 0.2.0.
- The marketing site's hero fallback `href` points at an older `-dev` build; live
  resolution picks this release up, but the static fallback needs the site repo.
- A plugin installed from a `link:` directory keeps its dependency spec when its contents
  change, so `plugin_manager install_bundle` reports `ambiguous-install` for a linked
  plugin whose bytes changed. The link already serves the new files; only a page reload is
  needed. Packed/tarball installs are unaffected.

## Install

Download `Mitsumeru-0.2.1-arm64.dmg`, open it, drag Mitsumeru to Applications. It is
notarized and stapled, so it opens on a double-click.

`latest-mac.yml` is the update manifest and must be uploaded beside the binaries.
