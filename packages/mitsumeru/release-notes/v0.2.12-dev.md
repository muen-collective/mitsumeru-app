# Mitsumeru 0.2.12-dev

Internal build — carries the `-dev` suffix; the update channel is `dev`.

Wraps DeepSeek Harness **0.2.2-rc.5** (from **0.2.2-rc.2**) — the release that now carries both
`latest` and `next` (published 2026-11-18). rc.3 (2026-11-13) and rc.4 (2026-11-17) were never
wrapped.

## What changed

- **The pin.** 0.2.2-rc.2 → **0.2.2-rc.5**.

- **Nothing of ours needed re-deriving, and that is the point of this cut.** The previous release
  rewrote both bundle patches to match *structure* instead of source lines, because rc.2 started
  shipping its client bundles minified. On rc.5 both applied on the first staging run —
  `patch-hero-brand-tagline.mjs` and `patch-muen-beta-badge.mjs` unchanged — so the shape-driven
  anchors have now survived three upstream releases, one of them a layout change.

- **The closure grew by one package.** 341 `@deepseek-ai/*` packages (release pins 89), **43,214
  files, 0 symlinks** (42,568 at rc.2). One name is new — **`dsh-deepseek-chat-import`** — and
  nothing was removed.

- **The composition patch is byte-identical to rc.2's.** No new rows, no new `!!js` gates, nothing
  hidden behind a profile-name condition between the two releases.

- **The missing-edge pin still earns its keep.** `dsh-client-ui-renderer@0.2.2-rc.5` still
  `require`s `@deepseek-ai/dsh-client-ui-slots` at module load and still declares it in neither
  `dependencies` nor `peerDependencies`, so the staging pin is unchanged and is still what keeps the
  packaged app from booting to a blank page. Cordis stays at 4.1.0.

- **`@muen/dsh-draw` still ships**, unchanged, along with the rest of `SHIPPED_PLUGINS`.

## The locale lesson this cut must not relearn

rc.2 introduced upstream `ja` dictionaries for its own namespaces, and 0.2.11-dev shipped with them
colliding against our legacy carrier `@muen/dsh-multi-lang-ui` — the frozen copy that registers
`ja` for `settings`, `cordis`, `job`, `feedback`, `slash.menu`. The first plugin to lose the race was
`dsh-client-ui-theme`, whose `apply()` registers `{zh,en,ja,…}` *before* it provides the `theme`
service; the throw killed it, and `layout`, `sidebar` and `chat` — all required — waited on `theme`
forever. The window came up empty.

**rc.5 still registers `ja` upstream** (checked in `dsh-client-ui-theme@0.2.2-rc.5`:
`locale.register(SETTINGS_NS,{zh,en,ja,es,fr,de,ru,pt})`). So the rule stands for every profile: the
frozen carrier stays out. `@muen/dsh-localize` owns the globe and the switcher and registers only its
own namespace, which cannot collide.

## Notarization is blocked by Apple, not by this build

The first `pnpm notarize:all` returned

```
HTTP status code: 403. A required agreement is missing or has expired.
```

and `xcrun notarytool history` answers with the same 403, so it is the Apple Developer account's
agreement (App Store Connect → Agreements, Tax, and Banking), not the keychain profile or this
machine. The Mac artifacts are **signed but unstapled**, which is why `pnpm verify:release` was not
run: it checks both staple layers and would fail for that reason alone. Publishing waits on the
team accepting the agreement; nothing else in the cut is outstanding.

Installed on the machine still: **0.2.11-dev (rc.2)** — that build is what the updater can serve
until this one is notarized and published.
